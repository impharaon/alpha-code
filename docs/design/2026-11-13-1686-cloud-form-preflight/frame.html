发起云端任务之前,先看到额度、余额和能不能发

打开云端任务的发送框时,原来那行「预留 US$…」的位置换成三行:你的余额和额度、这次要预留多少、现在能不能发。发不了时写原因,带上原来就有的「去登录」「打开余额支付」「去充值」按钮。这只是提示:「发起任务」按钮不会因此变灰,也不用等它查完。

与上一稿的关系

  • 起点:发送框没有设计稿(定制中心现行稿 #cloud-task 只画到详情页的「云端任务」事实行,不含发送框),所以改前 = 上线代码:cloud-form-box.tsx(目录描述的云能力)与 cloud-dispatch-box.tsx(旧版云条目),样式直接引用 extension-hub.css。
  • 不变:发送框的标题、说明、「发送到云端的内容」、输入框、按钮及其顺序和可用规则;发送后的进度、结果和报错行。
  • 改动:目录表单里「预留 US$…」那一行的位置换成预检的三行;旧版云条目在说明行之后、输入之前加同样的三行。查不到时目录表单回到原来那行「预留 US$…」。
  • 样式:每一行都是发送框里已有的样式 —— 普通说明行、「✓」成功行、红色提示行、原有的动作按钮;数字用详情页事实值的颜色。没有新组件、新颜色。
  • 文字:拒绝原因原样沿用今天发送失败时的句子;余额和额度的叫法与格式照账户弹层(「可用余额 ¥36.50」「5 小时额度 180 / 1,000」)。新写的只有:「正在查询额度…」「✓ 现在可以发起」「额度用完后用余额付 开 / 关」、人民币版的预留句,和已停用那一句。

改前改后宽 880 = 默认窗口 1280 × 800 下详情页内容列的宽度

改后是最常见的一种:能发。加的就是蓝框圈出的那几行。

目录表单 · 各状态以「云端深度调研」为例 · 宽 880

所有状态下「发起任务」都照常可点。表单本身没登录时已经写着「请先登录平台账号…」,这时不再显示预检区,免得同一件事说两遍;「登录已失效」只在表单可用、但查额度被拒时出现。

旧版云条目 · 各状态以「云端代码审查」为例 · 宽 880

旧版发送框原本没有预留行,三行加在说明之后、按钮之前;查不到时什么都不加,和今天一样。

已停用那句要你看一眼

任务类型已经在云端停用时,提交前就说清楚,不再落到「未能确认云端是否接收了任务」那句。推荐稍短的一句;另一个是原提议。

窄窗口与矮窗口

最长的一种(额度用完)放在窄窗口里。矮窗口取应用里唯一写明的最小窗口 520 高:去掉顶部 40 和页签 44,能看到 436 高。预检区顶在可见区最上面时,「发起任务」仍在虚线以上。

复用与缺口帧外

预检区的部分复用
位置目录表单里原来的预留行(data-cloud-hold)那一格;旧版云条目放在说明行之后的同一相对位置
余额额度行说明行 .codepuppy-ext-dnote;数字用详情页事实值 .codepuppy-ext-dfact-v 的颜色;叫法与格式取自账户弹层(codepuppy.sidebar.balance / fiveHour / sevenDay、¥ 两位小数、千分位)
预留句原预留行的句子 codepuppy.ext.cloudHold,换成人民币要一个新键
能发发送框里已有的成功行 .codepuppy-ext-dnote[data-ok](「✓ 已完成」那一行)
拒绝原因与动作红色提示行 .codepuppy-ext-dnote[data-err];句子与按钮来自 failureCopy / dispatchError 和已有的 .codepuppy-ext-add「去登录 / 打开余额支付 / 去充值」
缺的只缺文字:「正在查询额度…」「✓ 现在可以发起」「额度用完后用余额付」「开 / 关」、人民币预留句、已停用一句(进 failureCopy)。样式只缺一条:余额额度行里每一对「名称 值」不在中间断行(white-space: nowrap),否则窄窗口会把「额度用完后用余额付」拆成两行

待你拍板帧外 · 每条第一项是推荐

  • 已停用那句:「这项云端功能已停用，请在本机生成。」(推荐,短一个字、读起来更顺)/ 原提议「这项云端功能已停用，请改在本机生成。」
  • 查不到额度时:照今天的样子,不额外提示(推荐,不影响发送就不打扰)/ 加一行「暂时查不到额度」。
  • 平台给出发送框没有对应文案的拒绝原因时(例如这条线路的用量已停):只显示余额和额度,不下结论(推荐,不写新句子)/ 照今天的路径显示「未能确认云端是否接收了任务…」—— 这句在还没提交时是错的。
