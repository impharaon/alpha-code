# 报问题时能复制准确的构建身份

<!-- owner-opening -->
**谁会遇到**:owner 用桌面端发现问题、要告诉 agent「哪里不对」的时候。**遇到什么**:「还没发布的修复」「测试现场留下的状态」「真的回归了」三种情况看起来一模一样,处理方法却完全不同;现在没有简单办法说清「我看到问题时用的是哪个版本、哪个渠道、是不是开发版」。**为什么是问题**:过去已多次因此误判,去查代码,结果只是手上的包比修复旧。**不做会怎样**:不影响正常使用,只是每次报问题都要先花一轮来回确认版本。

## 用户与范围

- 用户：Code Puppy 桌面使用者（目前主要是 owner 报问题时）。
- 核心路径：点开侧栏底部的账户浮层 → 点版本那一行 → 身份信息进剪贴板 → 粘贴给 agent 或写进问题描述。
- 包括：复制一行构建身份；版本行上区分开发版、本机构建与正式发布版。
- **不包括**：自动上传诊断数据或未批准的信息采集；复制内容里不含账号、路径、项目名等个人信息。
- 假设与依赖：在 OpenCode 2 换代（alpha-code#1662）合入之后实施。
- 范围取舍：本期必做 = BR-01 至 BR-03。「关于」对话框暂不加同样的复制入口（一个入口够用）。

## 体验约定

- 用户路径：见核心路径。
- 交互与状态：账户浮层底部现有的「版本 0.1.26」一行变为可点；点一下复制，行内文字短暂变为「已复制」约 2 秒后恢复。非正式发布版在版本号后带一个小标记：开发渠道显示「开发版」，本机打出来的包显示「本机构建」；正式发布版不带标记。
- 文案：标记「开发版」「本机构建」；反馈「已复制」。
- 设计稿：复用账户浮层现有版本行（alpha-code#1187 的实现），标记用现有的小标签样式；属于现有组件内的小改，不另出稿。

## 业务规则

- **BR-01 复制的是正在运行的这个包的身份**：内容来自运行中的应用自身，不从源码目录或线上最新版本推断 —— INT-desktop/I-12，原票描述的「手上的包比修复旧」误判。
- **BR-02 复制内容固定为一行**：依次包含 产品名与版本号、渠道（正式／开发）、构建提交的短编号、构建时间、构建来源（正式发布／本机构建）、系统与芯片架构。例：`Code Puppy 0.1.26 · 正式 · 578c552 · 2026-11-05 · 正式发布 · macOS 15.3 arm64`。取不到的字段写「未知」，不省略、不编造 —— 同上。
- **BR-03 一眼可辨**：版本行上的标记与复制内容里的渠道、构建来源一致 —— 原票标题「开发版与正式版一眼可辨」。

## 用户会碰到的限制

无。

## 验收

| ID | Given / When / Then | 依据 |
| --- | --- | --- |
| AC-01 | 给定任意一个正在运行的桌面包；当用户点账户浮层里的版本行；则剪贴板里是 BR-02 规定的一行，其中版本号、渠道、构建提交与该包打包时的实际值一致，行内显示「已复制」约 2 秒 | BR-01、BR-02 |
| AC-02 | 给定开发渠道的包、本机构建的正式渠道包、正式发布的包各一个；则版本行分别显示「开发版」标记、「本机构建」标记、无标记，且与各自复制内容一致 | BR-03 |
| AC-03 | 给定一个取不到构建提交的包（例如从源码直接启动）；当用户复制；则该字段为「未知」，其余字段照常，应用不报错 | BR-02 |
| AC-04 | 复制内容里不出现用户名、家目录路径、账号或项目名 | 范围（不包括） |

原 AC-01、AC-02 草案已由上表取代（编号沿用）。
