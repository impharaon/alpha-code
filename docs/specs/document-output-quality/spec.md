# SPEC-document-output-quality｜助手做出的文档可以直接拿去用

用户让助手做一份报告、一套幻灯片或一张报表。现在做出来的文件只有文字和最基本的结构，没有图表、图片、版式，生成后也没有任何一步看成品，owner 的评价是「质量太差」。这份规格把做法换成 Anthropic 公开的文档技能，补上「看成品再改一轮」，并把需要的工具备到用户电脑上。

## 来源

- 意图：impharaon/alpha-work `docs/intents/INT-office.md` I-09（owner 2026-11-25 至 11-26，U-01 至 U-12）。
- owner 原话：「当前的插件查处质量太差了」（U-01）；授权按「本机模板 + 生成后看图自查」形成规格（U-02）；「Excel 的能力并入自研连接器，同意； 依赖 LibreOffice 等大件，就是大件可以。」（U-06）；「如果能用 claude 尽可能用claude 的」（U-07）；「首次使用时下载，对 Word PPT PDF 同样适用，我的建议都使用claude 的」（U-08）；「LibreOffice 来渲染」（U-09）；「HTML 和设计类也用 Claude 的，可以」（U-10）；LibreOffice 首次使用时按需下载（U-11）；批准本规格，OfficeCLI「不带」，小额实测「授权」（U-12）。
- 讨论与试验：同仓 `docs/intents/discussions/INT-office.md` 的 P-01、P-03、P-04、P-05，以及 Word、PPT、Excel 三次试验和渲染对比的数据。
- 相关规格：impharaon/alpha-work SPEC-first-party-excel（Excel 条目只有自研那一个，不变）、SPEC-cloud-image-understanding（不能看图的模型借助云端识图）；本仓 SPEC-office-layout-preview（给用户看的预览，不变）、SPEC-word-layout-and-typography。

## 用户与范围

- 用户：让助手产出文档的 Code Puppy 桌面端用户，多数用中文。
- 核心路径：用户说出要什么文档 → 助手生成文件 → 助手把成品渲染成图，自己检查并修一轮 → 用户拿到文件，并知道检查的结果。
- 包括：Word、Excel、PPT、PDF、网页（HTML）、设计类成品（海报、图示一类）六种；生成、渲染、自查与一轮修正；需要的工具送到用户电脑上；自研 Excel 连接器的能力补全；随应用带的中文模板。
- **不包括**：
  - 云端生成文档（2026-10-27 已关停，不恢复）。
  - 给用户看的文件预览（已有，SPEC-office-layout-preview）。
  - 读取用户给的文档（已有的读取工具不变）。
- 假设与依赖：
  - Anthropic 的文档技能与设计类技能是 Apache-2.0，可以随应用分发；技能里附带的标准文件（ISO、ECMA、微软的格式定义文件）没有许可证说明，核清之前不随应用分发。
  - LibreOffice 从我们自己的入口下载，属于「应用钉住版本的第三方固定文件」（impharaon/alpha-work SPEC-domestic-cloud-connectivity BR-09，v4，同日批准）。
  - 技能要用的 Node 运行环境由本仓 SPEC-connector-launchers 提供（v1，同日批准）；Python 用应用已经带的那一份。
  - 平台的模型现在都不能看图（网关不接收图片），自查时的渲染图经现有的云端识图理解。
  - 技能是为 Claude 写的。平台默认模型（deepseek-v4-flash）照着做能到什么程度还没有试验；owner 2026-11-26 授权了一次上限 50 元的实测，见「待决」。
- 范围取舍：
  - 现有的四个写入工具不再是生成文档的做法（P-03，owner U-08 定四种格式都用 Anthropic 的技能）；读取工具保留。
  - 不采用「网页转幻灯片」（试验里换字体后文字框重叠，图表没有数据）。
  - 不带 OfficeCLI（owner 2026-11-26「不带」，U-12）：试验里它做 Word 分页与 Excel 图表、打印版式的自查会查错，用户看成品已有应用自带的预览。

## 体验约定

- 用户路径：用户在对话里提出要求 → 工具卡片依次显示「生成」「渲染」「检查」→ 助手交付文件，并用一两句话说明检查了什么、修了什么、还有什么没解决。文件一生成就在项目里，用户随时可以点开应用自带的预览。
- 首次使用：第一次用到文档功能时，后台开始下载渲染组件，工具卡片显示下载进度；下载期间文件照常生成。
- 界面：复用现有的工具卡片与文件预览，不新增页面和组件，不另出设计稿。

## 业务规则

- **BR-01** 六种成品都按 Anthropic 对应技能的做法生成：Word、Excel、PPT、PDF 用四个文档技能，网页与设计类成品用设计类技能 —— I-09（U-08、U-10）。
- **BR-02** 生成的文件能包含该格式常用的要素。Word：目录、页眉页脚与页码、图片、图表、带样式的表格、编号与项目符号。PPT：版式与主题、图片、图表、表格、备注。Excel：公式、数字格式、列宽与冻结、条件格式、图表、下拉选项、打印设置。PDF：版面、图片、页眉页脚 —— I-09（U-01），P-01。
- **BR-03** 每份成品生成后都要渲染成图，由助手检查并至多修一轮，再交给用户；检查出来但没修好的问题如实告诉用户 —— I-09（U-02），P-01。
- **BR-04** Word、Excel、PPT 的自查以 LibreOffice 的渲染为准；PDF 直接转成图；网页与设计类成品用应用自带的浏览器内核渲染 —— I-09（U-09），P-05。
- **BR-05** Excel 另外核对两件事：重算后没有公式错误；助手读得到算出来的值，而不只是公式原文 —— P-05（试验：技能本身没有看图这一步，现有工具只返回公式原文）。
- **BR-06** 成品和渲染图里的中文正常：字体是指定的中文字体或同类字体，不缺字，不逐字混用不同字体 —— P-05；SPEC-word-layout-and-typography。
- **BR-07** 技能需要的运行环境由应用备好，用户不用安装任何东西。LibreOffice 在第一次用到文档功能时自动在后台下载，来源是我们自己的入口，国内不开代理也能下完，可以续传；下载好之后不联网也能用 —— I-09（U-06、U-08）；INT-execution I-18。
- **BR-08** LibreOffice 还没下载好时，Word、Excel、PPT 的成品先交付并写明版面还没有检查；LibreOffice 就绪后补做检查，并把结果告诉用户 —— I-09（U-12「不带」），P-05。
- **BR-09** 自研 Excel 连接器补上技能做不到、或用工具更稳的能力：读出算好的值与分区域读取、查看工作簿结构、透视表与切片器、迷你图、查找替换与排序。Excel 条目仍然只有自研这一个 —— I-09（U-06、U-07）；SPEC-first-party-excel BR-01、BR-02。
- **BR-10** 应用带一组中文模板，每种 Office 格式至少一个；用户没有说明样式时从模板出发，用户给了自己的模板或样例文件时沿用它的版式 —— I-09（U-02）。
- **BR-11** 技能改成适合本应用：用应用备好的运行环境与路径，不假设电脑上预装了什么，不假设模型是 Claude，补上中文字体与中文排版的指导，Windows 上同样成立 —— P-03（U-08 转为共识）。
- **BR-12** 网页成品离线能打开：不引用国外的字体与脚本地址 —— P-02。
- **BR-13** 生成、渲染都在本机完成，文档内容不离开电脑；渲染工具自己不联网，也不自动更新。离开电脑的只有一种情况：模型不能看图时，渲染图经现有的云端识图理解 —— I-09（U-02）；SPEC-cloud-image-understanding。
- **BR-14** 随应用分发的技能与第三方组件带上各自的许可证与署名 —— P-03。
- **BR-15** 以上能力在 Windows 上同样提供 —— impharaon/alpha-work INT-safety U-34「还需要考虑 windows 系统，现在没发 windows 包后续是需要发的」。

## 用户会碰到的限制

| 用户碰到什么 | 多做、多懂什么 | 用户能接受吗 | 换来什么 | 出处 |
| --- | --- | --- | --- | --- |
| 做一份文档比现在慢：多了渲染、检查和可能的一轮修改 | 多等一会儿，卡片上看得到进行到哪一步 | owner 授权 | 版面问题在交付前被发现 | U-02 授权「生成后看图自查」 |
| 第一次用文档功能时后台下载约 300 MB（装好后占约 800 MB 磁盘） | 无操作；这一次 Word、Excel、PPT 的版面检查要等它下完 | owner 提出 | 安装包不变大 | U-08「首次使用时下载」 |
| 平台模型不能看图：自查的渲染图会上传到云端识图并按张计费 | 无操作；每份文档多一笔小额费用 | 已批准的现有规则；自查本身由 owner 授权 | 不能看图的模型也能查版面 | SPEC-cloud-image-understanding；U-02 |
| 只修一轮：一轮没修好的问题会告诉用户，不再自动重试 | 需要时让助手继续改 | owner 授权的做法 | 时间与费用有上限 | U-02 的原方案「至多修一轮」 |
| 渲染图与 Word、Excel 本体里的样子可能有细小差别（字体替换、行距） | 重要文件自己用 Office 打开看一眼 | 技术水平所限 | — | 试验数据见讨论记录 |

## 待决

- 平台默认模型照着技能做能到什么程度。AC-01 至 AC-03 的数值（9/10、10/11、11/12）是按试验里能力强的模型的成绩写的，默认模型没有试过。owner 2026-11-26 已授权一次实测（用平台默认模型各做 3 次 Word、PPT、Excel，费用上限 50 元，记在 owner 的平台账号上）。实测后这三条的数值如需修订，按规格变更的程序提请 owner；不需要修订则把这一条移出。

规格批准不等于开发授权；开发未授权。
