# 对话改不了决定运行什么程序、哪些工具免问、凭据交给谁的配置

## 来源

- 意图：impharaon/alpha-work `docs/intents/INT-safety.md` I-13（owner 2026-11-14 以 U-10「全部按你的推荐。」批准）。条文：「智能体获批的一次写文件就能改掉插件放行策略的输入」；方向：「这些位置从围栏可写范围里拿掉或改为只读,必要的写入改由主进程代办」。
- 与密钥保护的关系：[SPEC-stored-credentials-fence](../stored-credentials-fence/spec.md) 只承诺对话读不到、改不了凭据存放位置；「对话改写围栏内可写的配置，把一份被合法代入的凭据引到别处」这一类由本规格关闭。owner 2026-11-20 同意这样分两部分交付（原话见「批准记录」）。
- 发现依据（2026-11-19 至 20，真引擎 + 生产围栏 profile + 假数据）：对话里一次写入可以换掉连接器的启动命令、覆盖模型的程序包（假密钥被送进假模块）、改工具策略为放行、往引擎库写两类放行记录，四项全部成功；另查明围栏内可写的 `~/.zsh_sessions` 与 `~/.zcompdump*` 会被围栏外的 shell 执行。
- 技术设计：[DESIGN engine-config-fence](design.md)（两轮独立设计审查）。

## 用户与范围

- 用户：使用 Code Puppy 桌面端的用户。用户自己的流程不变：安装、启用、停用连接器与扩展包，添加模型与密钥，改设置，应用启动，都与今天一样，不新增步骤、提示、等待或设置。
- 包括（受保护位置，唯一清单在设计 §4.1）：
  - Code Puppy 的状态目录（连接器配置 `codepuppy.jsonc`、安装账本、技能指针、自动化任务等）；
  - Code Puppy 合成的引擎配置目录（引擎配置文件与模型底表）；
  - shell 环境快照、`codepuppy.env`、入口地址文件、连接记录、界面设置存储；
  - 引擎全局配置目录、`~/.opencode`、主目录下的 `opencode.json` / `opencode.jsonc`；
  - 工具策略文档。
- 还包括：引擎库里三类会让放行或配置活过本回合的记录；围栏内可写、而会被围栏外 shell 执行的两处（`~/.zsh_sessions`、`~/.zcompdump*`）。
- 不包括（设计 §6 的残留，各带前提）：
  - 用户允许过的项目里，项目自带的配置按装载时的内容生效，包括对话在那里写进去的改动（INT-safety I-28）。
  - 包管理器缓存里之后会被执行的程序本体可被对话替换（I-29）。
  - 受保护目录里用户自己放的、指向保护范围之外的软链，其目标按目标所在位置的规则（I-27）。
  - 用户自己的 PATH 里含可写目录；引擎库里其余记录；模型读的正文类文件；本规格安装之前留下的内容、硬链别名与仍在运行的旧进程；非 macOS 平台没有围栏（引擎读取规则与主进程写者照样生效）。

## 业务规则

- **BR-01** 被围栏的进程树里，任何进程都不能新建、修改、替换、改名、删除、硬链或克隆受保护位置，也不能新建、改名、删除它们任何一级上级目录节点；受保护位置本身是软链时，其真实目标同样受保护。用户运行期打开的项目不改变这一点。
- **BR-02** 引擎判定权限时不采用引擎库里的项目级已存批准；会话行上的规则只有「拒绝」生效；引擎不装载 wellknown 缓存的配置文档。
- **BR-03** 原来在围栏内写受保护位置的写者（引擎配置文件、模型底表、配置种子及其监听、工具策略修改）改由主进程执行；写失败有具名日志并走既有失败路径，不静默丢掉用户的设置。
- **BR-04** 用户自己的流程照常：经设置页、定制中心或在应用外编辑这些配置；用户的改动与安装在引擎不重启的情况下生效；升级后已有的连接器、模型、设置、工具策略不变。
- **BR-05** 「用户打开的项目当场可写」（SPEC-child-process-write-fence AC-05）不受影响。项目本身就是受保护位置或在其内时不放行，并显示一句说明。
- **BR-06** 围栏内不能再写 `~/.zsh_sessions` 与 `~/.zcompdump*`；应用内终端没有可见变化。
- **BR-07** 计划文件存放在引擎数据目录下（`~/.local/share/opencode/plan/`）。任何进程，包括应用自己，都不在任何层级创建 `.opencode`；`~/.opencode` 整个受保护。

## 用户会碰到的限制

- 对话里的工具与命令不能直接改受保护位置。例如让助手直接编辑 `~/.config/opencode/`、`~/.opencode/` 或 `codepuppy.jsonc`，会得到「无权写入」。用户经设置页、定制中心或在应用外自己编辑不受影响。依据：I-13 获批条文。
- 把受保护位置或它里面的文件夹当项目打开时，这个项目不可写，显示一句说明、没有按钮：「这个文件夹是 Code Puppy 或引擎存放配置的位置，对话里不能写入。」位置与样式同 SPEC-child-process-write-fence AC-08 的三句说明。
- 计划文件改存到 `~/.local/share/opencode/plan/`。已有 `~/.opencode/plan/` 里的文件不搬，对话里仍可读、不能再改。「清除数据」勾选引擎数据时，计划文件一并删除。依据：owner 2026-11-20 在三个选项里选 A。
