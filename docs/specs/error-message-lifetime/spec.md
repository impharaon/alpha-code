# SPEC-error-message-lifetime｜界面报错信息的显示时长与恢复后的处理

Code Puppy 桌面端的报错弹出提示现在永不自动消失、不合并、恢复后也不清,启动时容易叠出一堆。本规格让提示跟着问题走:问题没了提示就没了,还在的问题有一个安静的地方可查。

## 来源
- 意图 [INT-error-message-lifetime](https://github.com/impharaon/alpha-work/blob/main/docs/intents/INT-error-message-lifetime.md):I-01 至 I-06,owner 2026-11-12 批准(U-02「同意，报错那几条建议转成正式需求」);原则 P-01、P-02、P-03。
- 现状事实见该意图的讨论记录(alpha-code@039f7715e1 只读盘点)。

## 用户与范围
- 用户:Code Puppy 桌面端所有用户。
- 核心路径:后台出了问题 → 用户看到一条提示 → 问题恢复则提示自动消失;没恢复则提示收起,状态入口上有标记,点开可看可处理。
- 包括:Code Puppy 自己的弹出提示(`codepuppy-ui/Toast.tsx` 这一套)的显示时长、合并、恢复后清除;一个「未恢复问题」的状态入口;启动阶段的静默。
- **不包括**:会话时间线里的失败记录(属于历史);已经跟随状态自动消失的横幅和状态行(模型目录、配置损坏、工具服务连接行)的现有行为;运行时恢复对话框;报错文案本身的改写;上游应用自带的另一套提示。
- 假设与依赖:在 OpenCode 2 换代(alpha-code#1662)合并之后实施,基于换代后的界面数据层。
- 范围取舍:本期必做 = BR-01 至 BR-05。引擎不可用横幅、契约不兼容横幅保持现状(本来就跟随状态)。

## 体验约定
- 用户路径:见核心路径。
- 交互与状态:弹出提示(出现 / 悬停暂停 / 自动消失 / 恢复即清);状态入口在侧栏底部、账户按钮上方(与「更新已就绪」同位置),无问题时不显示,有未恢复问题时显示「N 个问题未恢复」,点开向上弹出列表,每条有原因和可做的操作;侧栏收起时由「显示侧边栏」按钮上的小点提示。
- 文案:沿用现有报错文案;入口与列表的新文案以设计稿为准。
- 设计稿:`docs/design/current/shell-sidebar/design.html` @ 089669ea00(锚点 `#problems`、`#toast-lifetime`),owner 2026-11-12 批准;增量稿 `docs/design/2026-11-12-error-message-lifetime/frame.html` @ 244a7c26ec。

## 业务规则
- **BR-01 恢复即清**:由后台状态引起的提示(工具服务连接、模型目录同步、扩展警告、云端运行保存等),对应状态恢复后立即自动消失,不需要用户点 × —— I-02、I-04、P-01。
- **BR-02 未恢复的收进入口**:后台状态类提示显示 8 秒后收起(鼠标悬停或键盘聚焦时不计时);只要问题仍未恢复,状态入口显示未恢复问题的数量,点开可看到每条的原因和可做的操作;问题恢复后从入口移除。用户点 × 只表示「看到了」:提示关闭,问题未恢复就仍留在入口;入口里的条目不能手动删除 —— I-01、I-04、P-01。
- **BR-03 同因合并**:同一来源、同一原因的提示同一时间只显示一条,再次发生时更新这一条而不新增,且不重新计时;提示已收起而问题未恢复时再次发生,不重新弹出,只更新入口里那一条 —— I-05、P-02。
- **BR-04 启动静默**:应用启动后的头几秒内,会自动重试的后台故障不弹提示;自动重试结束仍失败的,按 BR-02 处理(默认静默窗口 10 秒,可回退的默认值)。静默窗口内出现的、需要用户处理的提示(如进入项目时的「部分内容未能导入」)不弹出,直接进入状态入口并计数 —— I-03、I-05、P-02。
- **BR-05 需要用户处理的保留**:启动静默窗口之外,用户刚做的操作失败,或需要用户动手才能解决(重新登录、修配置、授权)的提示,保留到用户处理、手动关闭或离开当前页面,不受 8 秒限制 —— I-06、P-03。

- **BR-06 工具服务连不上不弹提示**:工具服务(连接器)连接失败只进入状态入口(原因与操作),重连后自动移除;需要重新登录的服务作为需用户处理项进入口(操作为去授权);用户或总开关停用的服务不算问题、不进入口。启动 10 秒静默窗口结束后才首次读取工具服务状态 —— owner 2026-11-12 裁决(今天没有这条弹出提示,不新增)。

## 用户会碰到的限制
无。本规格只减少用户要做的事(不再逐条点 ×)。

| ID | Given / When / Then | 依据 |

| AC-01 | 给定一个工具服务断开并已列在状态入口里;当它重连成功;则 1 秒内该条从入口消失(只有这一条时入口一并消失);全程不弹提示 | BR-01、BR-06 |
| AC-02 | 给定一个后台故障提示正在显示且问题未恢复;当过了 8 秒且鼠标不在提示上;则提示收起,状态入口显示数量 1,点开能看到这条的原因和操作 | BR-02 |
| AC-03 | 给定鼠标悬停在一条后台故障提示上;当超过 8 秒;则提示仍在,移开后才开始计时 | BR-02 |
| AC-04 | 给定同一原因在 1 秒内被报告 3 次;则屏幕上只有一条该提示,状态入口也只计 1 | BR-03 |
| AC-05 | 给定应用启动时两个工具服务首次连接失败、随后自动重连成功;则全程没有任何提示,入口也不出现标记 | BR-04、BR-01、BR-06 |
| AC-06 | 给定应用启动时一个工具服务连接失败且自动重试后仍失败;则静默窗口结束后入口显示它(数量 1,有原因和操作);不弹提示 | BR-04、BR-02、BR-06 |
| AC-07 | 给定用户点了「删除会话」而操作失败;则失败提示一直显示,直到用户关闭它或离开当前页面,超过 8 秒也不消失 | BR-05 |
| AC-09 | 给定应用启动并进入一个项目,进入时有两条「需要用户处理」的提示产生;则启动后 10 秒内屏幕上没有弹出提示,状态入口显示数量 2,点开能看到这两条及其操作 | BR-04 |
| AC-10 | 给定一条后台故障提示已收起、问题未恢复;当同一原因再次发生;则不弹出新提示,入口数量不变 | BR-03 |
| AC-11 | 给定一条后台故障提示正在显示;当用户点 ×;则提示关闭,问题未恢复时入口数量为 1;列表里的条目没有删除按钮 | BR-02 |
| AC-08 | 给定状态入口里有 2 条未恢复问题;当其中一条恢复;则数量变为 1;全部恢复后入口标记消失 | BR-01、BR-02 |

无。8 秒与 10 秒为可回退的默认值。
