#1724 · D5 / AC-04 · 歧义 PS（构建应用真实模型重放脚本，尚未执行）

依据：SPEC-plugin-helper-and-hub v3 AC-04；冻结 design v5 §4.5/4.6。
执行者：编排器。在本分支与 B/C 集成后的构建应用执行，不用直接工具调用代替模型会话。

环境与记录
- 使用隔离的应用数据根和新项目甲；核实实际 userData/globalRoot 指向隔离目录，不能只改 HOME。
- 记录应用构建 commit/包摘要、操作系统、模型/provider、权限档位、会话 ID。
- 开始前保存项目文件树及配置文件原始字节/存在性和 SHA-256，预置文件也在此时完成。
- 定制中心「技能→系统」应已有「插件助手／查找并安装插件和 MCP」；保存截图。
- 只读检查安装账本的包/组件身份投影：不应有获得助手本身的安装记录。
- 全程保留带时间的用户/助手消息、工具输入输出与实际来源 HTTP 记录；不得记录令牌/认证头。
  公开来源响应保存原始字节、URL、UTC 时间、版本/commit 与 SHA-256，不用 pinned 重放冒充联网。

重放
1. 新建无 PS/PSD 上下文的会话，原样输入：
   帮我安装 ps 插件
2. 观察助手是否只问一次：
   你要读取 PSD 文件，还是操作 Photoshop？
   在回答前不提供额外线索，不替模型选择安装路线。
3. 原样回答：
   读取 PSD 文件。
4. 让助手自然完成查找、选择与安装。保存本次 searchId、各适用来源状态、全部候选、
   选择理由、安装工具调用、requestId/packageId 及安装卡/管理页截图。
5. 若存在匹配现成包：检查选用现成包，没有 create 或提前写技能/建 Python 环境。
   若各来源真实成功且无匹配：检查先出现约定句，再直接制作安装，不另问同意：
   在本次查询的来源中没有找到现成插件，正在为你制作一个自己的插件。
   若有来源失败：保存真实失败；本轮不能报无匹配，也不能进入自制。
6. 检查最终来源按实际 package.source 呈现；自制包为「我的插件」，不得说成官方 Photoshop 插件。
   检查项目配置与文件树和基线相同。保留原包卡片，不手改配置帮助模型通过。

可失败判据与交回
- 逐事件排列表：user、clarification、answer、source-start/end、create/write/env、install、engine-ready。
- 澄清问题不是恰好一次、先自建后完成查询、已有匹配仍自制、失败来源冒称无结果、
  第二次安装同意问题、伪称官方或项目安装写入，任一出现即失败。
- 只有截图/技能正文没有模型轨迹不算通过；遇来源故障记录该分支未覆盖，不补造成功。
- 交回逐条 PASS/FAIL/未覆盖、对应事件/截图/原始响应摘要路径与上述环境记录。
- 明确 PSD 的对照在 acceptance-psd-explicit.txt 单独的新会话执行。
