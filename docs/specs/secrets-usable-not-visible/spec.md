# SPEC-secrets-usable-not-visible｜密钥文件程序可以用、助手看不到

用户让助手运行、调试要用密钥的项目时，程序照常拿到密钥，助手看到的任何内容里都没有密钥的值。

## 来源

- 意图：impharaon/alpha-work `docs/intents/INT-safety.md` I-45（owner 2026-11-25，U-30、U-32、U-33）。
- owner 原话（U-32）：「就是是否这些密钥，只可以使用，不可以发送给模型。」「这个是否也适当放松，但是要有一些名单中的 比如 ssh 密钥不可以直接读。」授权形成规格（U-33）：「可以，形成规格。」
- 讨论与事实：同仓 `docs/intents/discussions/INT-safety.md`「2026-11-25 续」一节的 P-06、P-08。

## 用户与范围

- 用户：在 Code Puppy 里让助手处理项目的人，项目里或电脑上放着密钥。
- 核心路径：用户让助手运行一个要用密钥的程序；程序正常工作；助手收到的结果里没有密钥的值。
- 包括：受保护名单；读文件工具对名单内文件的处理；交给助手的工具结果的遮盖；「全部批准」档读项目外文件不再询问。
- 平台：macOS 与 Windows 都适用。本规格的规则不依赖写入围栏，Windows 上同样生效；名单按平台列出各自的位置。Windows 包尚未发布，发布时在真机上验收。依据 owner 2026-11-25「还需要考虑 windows 系统，现在没发 windows 包后续是需要发的。」
- 不包括：
  - 自动化任务。它读 `.env` 一类文件仍按 SPEC-unattended-run-permissions BR-03 立即拒绝。
  - 用户自己粘贴进对话的密钥。
  - 应用自己保存的凭据，已由 SPEC-stored-credentials-fence 管。
  - 阻止程序把密钥发到网络上。联网范围另有规则，不识别内容。
- 假设与依赖：遮盖发生在工具结果进入对话之前（见「待决」）。
- 范围取舍：不在操作系统层禁止读这些文件，否则程序自己也读不到，`git` 也用不了 SSH 密钥。

## 体验约定

- 助手用读文件工具读到名单内的文件时，不出现批准卡片。工具卡片里显示变量名，值显示为遮盖符，并带一句说明：「这是密钥文件，值不提供给助手；程序运行时照常能用。」
- 命令输出或其它工具结果里被遮盖的地方，显示同样的遮盖符。
- 界面：复用现有工具卡片的文本区，不新增界面。

## 业务规则

- **BR-01** 受保护名单是一份随应用发布的单一名单，列出放密钥的文件与位置。项目里：`.env`、`.env.*`（示例文件如 `.env.example` 除外），以及其它语言和工具里放密钥的同类文件。用户主目录里：SSH 密钥、云厂商与容器的登录凭据、GnuPG、钥匙串、浏览器保存的登录数据；Windows 上是这些内容在 Windows 里的对应位置。批准卡片的风险标注用同一份名单 —— INT-safety I-45（U-32；Windows：U-34）。
- **BR-02** 助手的读文件工具读名单内的文件时不询问，也不返回密钥的值：环境变量一类的文件返回变量名，值以遮盖符代替；其它文件（如私钥）只返回一句说明。三个权限档一致 —— I-45（U-32）。
- **BR-03** 交给助手的任何工具结果（读文件、命令输出、连接器结果）里，原样出现名单内文件中的密钥值或私钥内容时，先替换成遮盖符。进入对话记录和显示在界面上的也是遮盖后的内容。（v2）遮盖的对象是名单内文件在命令运行前后能读到的值；命令运行中临时生成、打印、再删掉的值，以及加密保存、由程序解密后才输出的值，不在其内 —— I-45（U-32）；impharaon/alpha-work INT-safety U-38（owner 2026-11-26「好的。」）。
- **BR-04** 程序不受影响：命令和连接器运行时照常读取、使用这些文件 —— I-45（U-32「只可以使用」）。
- **BR-05** 「全部批准」档读取项目外的文件不再询问；名单内的位置按 BR-02、BR-03 处理。「请求审批」档与「只读」档不变 —— I-45（U-32、U-33）。
- **BR-06** 名单内文件里明显不是密钥的值（例如端口号、开关、环境名）不遮盖，由随名单发布的规则判定 —— 讨论 P-08（Claude 的建议，owner 2026-11-25 随本规格批准）。

- **BR-07**（v2）遮盖这一步本身出错时，这一次的输出整段不交给助手、也不显示在工具卡片和对话记录里，助手和用户都看到一句「这次输出没能遮盖，已隐藏」；命令本身照常执行完 —— impharaon/alpha-work INT-safety U-38（owner 2026-11-26「好的。」）。
## 用户会碰到的限制

| （v2）遮盖这一步出错时（很少见），这一次的输出看不到，只有一句说明 | 需要时让助手换个方式重跑 | owner 2026-11-26「好的。」 | 不会因为出错把密钥原样放出 | impharaon/alpha-work INT-safety U-38（owner 2026-11-26「好的。」） |
| 「全部批准」档下助手读项目外的文件不再先问 | 无 | owner 提出 | 少打断 | U-32「适当放松，但是要有一些名单」 |

## 待决

无。v1 的待决已解决：引擎的「工具执行后」挂点能改写成功的结果（真引擎探针）；命令的实时输出与后台输出要在引擎写文件前遮盖，需要新增一个引擎挂点，owner 2026-11-26 允许这一处引擎改动（impharaon/alpha-work INT-safety U-38（owner 2026-11-26「好的。」））。
