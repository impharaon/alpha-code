# SPEC-secrets-usable-not-visible｜密钥文件程序可以用、助手看不到

用户让助手运行、调试要用密钥的项目时，程序照常拿到密钥，助手看到的任何内容里都没有密钥的值。

## 来源

- 意图：impharaon/alpha-work `docs/intents/INT-safety.md` I-45（owner 2026-11-25，U-30、U-32、U-33）。
- owner 原话（U-32）：「就是是否这些密钥，只可以使用，不可以发送给模型。」「这个是否也适当放松，但是要有一些名单中的 比如 ssh 密钥不可以直接读。」授权形成规格（U-33）：「可以，形成规格。」
- 讨论与事实：同仓 `docs/intents/discussions/INT-safety.md`「2026-11-25 续」一节的 P-06、P-08。

## 用户与范围

- 用户：在 Code Puppy 里让助手处理项目的人，项目里或电脑上放着密钥。
- 核心路径：用户让助手运行一个要用密钥的程序；程序正常工作；助手收到的结果里没有密钥的值。
- 包括：受保护名单；读文件工具对名单内文件的处理；交给助手的工具结果的遮盖；「全部批准」档读项目外文件不再询问。
- 不包括：
  - 自动化任务。它读 `.env` 一类文件仍按 SPEC-unattended-run-permissions BR-03 立即拒绝。
  - 用户自己粘贴进对话的密钥。
  - 应用自己保存的凭据，已由 SPEC-stored-credentials-fence 管。
  - 阻止程序把密钥发到网络上。联网范围另有规则，不识别内容。
- 假设与依赖：遮盖发生在工具结果进入对话之前（见「待决」）。
- 范围取舍：不在操作系统层禁止读这些文件，否则程序自己也读不到，`git` 也用不了 SSH 密钥。

## 体验约定

- 助手用读文件工具读到名单内的文件时，不出现批准卡片。工具卡片里显示变量名，值显示为遮盖符，并带一句说明：「这是密钥文件，值不提供给助手；程序运行时照常能用。」
- 命令输出或其它工具结果里被遮盖的地方，显示同样的遮盖符。
- 界面：复用现有工具卡片的文本区，不新增界面。

## 业务规则

- **BR-01** 受保护名单是一份随应用发布的单一名单，列出放密钥的文件与位置。项目里：`.env`、`.env.*`（示例文件如 `.env.example` 除外），以及其它语言和工具里放密钥的同类文件。用户主目录里：SSH 密钥、云厂商与容器的登录凭据、GnuPG、钥匙串、浏览器保存的登录数据。批准卡片的风险标注用同一份名单 —— INT-safety I-45（U-32）。
- **BR-02** 助手的读文件工具读名单内的文件时不询问，也不返回密钥的值：环境变量一类的文件返回变量名，值以遮盖符代替；其它文件（如私钥）只返回一句说明。三个权限档一致 —— I-45（U-32）。
- **BR-03** 交给助手的任何工具结果（读文件、命令输出、连接器结果）里，原样出现名单内文件中的密钥值或私钥内容时，先替换成遮盖符。进入对话记录和显示在界面上的也是遮盖后的内容 —— I-45（U-32）。
- **BR-04** 程序不受影响：命令和连接器运行时照常读取、使用这些文件 —— I-45（U-32「只可以使用」）。
- **BR-05** 「全部批准」档读取项目外的文件不再询问；名单内的位置按 BR-02、BR-03 处理。「请求审批」档与「只读」档不变 —— I-45（U-32、U-33）。
- **BR-06** 名单内文件里明显不是密钥的值（例如端口号、开关、环境名）不遮盖，由随名单发布的规则判定 —— 讨论 P-08（Claude 的建议，随本规格请 owner 批准）。

## 用户会碰到的限制

| 用户碰到什么 | 多做、多懂什么 | 用户能接受吗 | 换来什么 | 出处 |
| --- | --- | --- | --- | --- |
| 助手看不到密钥的值，不能替用户核对「这个密钥填得对不对」 | 需要时自己看文件，或让助手写一段不打印密钥的检查脚本 | owner 提出 | 密钥不进对话，不发给模型服务方 | U-32「只可以使用，不可以发送给模型」 |
| 遮盖按原样匹配：恰好与某个密钥值相同的普通文字也会被遮；程序把密钥编码或拆开后再输出的，遮不住 | 知道遮盖不是绝对保证 | 待 owner 批准 | 同上 | 讨论 P-08 的边界 |
| 「全部批准」档下助手读项目外的文件不再先问 | 无 | owner 提出 | 少打断 | U-32「适当放松，但是要有一些名单」 |
