# SPEC-unattended-run-permissions｜没人在场的任务不再空等批准

用户设好的自动化任务到点运行时没有人坐在屏幕前。现在任务一用到连接器、插件或云端工具,就弹出一个没人会点的批准请求,挂 300 秒后按拒绝处理,这一步失败。本规格让这类任务在需要批准的那一刻直接得到结论:权限允许就执行,不允许就立即停下并写明原因。

## 来源
- 意图 [INT-upstream-upgrade-readiness](https://github.com/impharaon/alpha-work/blob/main/docs/intents/INT-upstream-upgrade-readiness.md) I-11,owner 2026-11-12 批准(U-12「对的，比如用户是全部批准的权限就应该不要询问。还需要检查就是基本上所有的都是一样的操作，还有哪些需要这样改。」)。
- 现状事实:`engine/1662-opencode2` @ 713727444b 只读盘点(2026-11-12);0.1.26 行为相同,不是换代退步。
- Story:待建。

## 现状(盘点结论)
- 等待在 `packages/core/src/permission.ts`:默认 300 秒,超时后请求撤销、该步按中断失败,自动化记为失败。
- 自动化任务用的是两个固定的自动化 agent(只读档、标准档),两者都把「非内置工具」设成询问;调度器建会话时不读用户的任何权限设置。
- 引擎已有「无人值守」开关(允许规则允许的、其余立即拒绝、明确禁止的仍禁止),但只用在定时检查上,从未用在真正的任务回合上。
- 对话框里的「全部允许」档只存在界面内存里;设置里的「自动批准」只是界面替用户点批准,引擎都看不到。

owner 问的「还有哪些地方是同样的情况」,逐条结论:

| 入口 | 没人在场时会怎样 | 本规格是否处理 |
| --- | --- | --- |
| 桌面本地自动化任务(定时与手动触发) | 空等 300 秒后失败 | 处理(BR-01 至 BR-04) |
| 新建自动化时「一句话解析」的那次模型调用 | 理论上会等 300 秒,实际很少用到工具 | 处理(同一规则) |
| 自动化运行中连接器向用户要补充信息(MCP elicitation) | 没有超时,会一直挂到任务总时限 | 处理(BR-05) |
| 对话里的子任务、后台子任务、子任务完成后唤醒主对话 | 等 300 秒;但这是用户自己开的对话,批准卡片是给用户看的 | 不处理,行为不变 |
| 应用重启后续跑的对话 | 同上 | 不处理 |
| 命令行非交互运行 | 已经是立即拒绝或带参数全部批准,不会挂 | 无需处理 |
| 云端定时任务与云任务 | 在云端执行,本机没有回合 | 无需处理 |
| 标题、摘要、压缩等内部小任务 | 不调用工具 | 无需处理 |
| 提问工具、装扩展、访问项目外目录 | 自动化 agent 本来就禁止这些,立即拒绝 | 无需处理 |

## 用户与范围
- 用户:在桌面端设了自动化任务的用户。
- 核心路径:任务到点运行 → 用到连接器等工具 → 权限允许则直接执行并继续;不允许则这一步立即失败,运行记录里写明是哪个工具、去哪里放行。
- 包括:桌面本地自动化任务的整个回合;自动化的一句话解析;自动化运行中的连接器补充信息请求。
- **不包括**:有人在场的对话(批准卡片与 300 秒等待保持现状);新增权限档位或新的设置项;云端任务;命令行。
- 假设与依赖:在 OpenCode 2 换代(alpha-code#1662)合入之后实施。
- 范围取舍:本期必做 = BR-01 至 BR-05。「对话里的子任务没人看时怎么办」不采纳 —— 那是用户在场的对话,保留批准卡片。

## 体验约定
- 用户路径:见核心路径。
- 交互与状态:不新增界面。自动化运行记录里已有的失败原因一行,显示新的原因文案。
- 文案:「「<工具名>」需要你先确认(它的来源发生了变化或已被停用),自动化任务运行时没有人可以确认。到 设置 → 工具 处理后,下次运行即可使用。」只读档任务用到写入类工具时:「这个任务是只读档,不能使用「<工具名>」。」
- 设计稿:复用自动化面板运行记录的现有失败行,不新画。

## 业务规则
- **BR-01 不等人**:自动化任务的回合里,任何需要批准的请求都在 1 秒内得到结论,不显示批准卡片,不进入 300 秒等待 —— I-11。
- **BR-02 标准档按「全部允许」对待已启用的工具**:标准档的自动化任务使用连接器、插件、云端工具时,只要该工具在 设置 → 工具 里是启用状态,就直接执行,包括用户单独设为「每次询问」的工具 —— I-11,U-12「用户是全部批准的权限就应该不要询问」;owner 2026-11-12 裁决「放行」。
- **BR-03 仍然立即拒绝的**:用户在 设置 → 工具 里停用的工具、身份发生变化待确认的工具、读取 `.env` 一类敏感文件、以及自动化 agent 本来就禁止的动作(提问、装扩展、派子任务、访问项目外目录),在自动化里一律立即拒绝,不因 BR-02 放宽 —— owner 的「放行」只针对「每次询问」这一档;其余是现有的禁止项,本规格不改。
- **BR-04 只读档不变**:只读档的自动化任务不因本规格多获得任何工具;用到不允许的工具时立即拒绝 —— 同上。
- **BR-05 连接器要补充信息时立即谢绝**:自动化运行中连接器向用户索要补充信息的请求立即按「用户未提供」答复,不挂起 —— I-11「还有哪些需要这样改」。
- **BR-06 原因说得清**:因 BR-03、BR-04、BR-05 失败的那一步,运行记录写明工具名和放行办法(文案见体验约定),不再显示为超时 —— I-11。

## 用户会碰到的限制

| 用户碰到什么 | 多做、多懂什么 | 用户能接受吗 | 换来什么 | 出处 |
| --- | --- | --- | --- | --- |
| 设为「每次询问」的工具在自动化里会不经询问直接执行 | 不想让自动化用它,要在 设置 → 工具 里停用它,或把任务设为只读档 | owner 已裁决接受 | 自动化任务不会因为没人批准而失败 | owner 2026-11-12「放行」 |

## 验收
| ID | Given / When / Then | 依据 |
| --- | --- | --- |
| AC-01 | 给定一个标准档自动化任务,要用到一个已启用、未单独设为询问的连接器工具;当任务运行;则该工具被调用且成功,全程没有批准请求产生,运行记为成功 | BR-01、BR-02 |
| AC-02 | 给定同样的任务,但该工具被用户设为「每次询问」;当任务运行;则该工具被调用且成功,全程没有批准请求产生 | BR-01、BR-02 |
| AC-08 | 给定标准档自动化任务用到一个身份发生变化待确认的工具,或一个已停用的工具;当任务运行;则这一步在 1 秒内失败,没有批准卡片出现,运行记录的失败原因包含工具名和处置办法 | BR-01、BR-03、BR-06 |
| AC-03 | 给定一个只读档自动化任务用到写入类连接器工具;当任务运行;则这一步在 1 秒内失败,原因写明任务是只读档 | BR-04、BR-06 |
| AC-04 | 给定一个标准档自动化任务试图读取 `.env`、派子任务或访问项目外目录;当任务运行;则与改动前一样被拒绝,且在 1 秒内 | BR-03 |
| AC-05 | 给定自动化运行中一个连接器向用户索要补充信息;则该请求在 1 秒内被谢绝,任务继续或按连接器的返回失败,不会挂到任务总时限 | BR-05 |
| AC-06 | 给定用户在对话框里用「询问」档发起对话并用到同一个工具;则仍显示批准卡片,等待行为与改动前一致 | 范围(不包括) |
| AC-07 | 给定新建自动化时的一句话解析;当解析过程中出现需要批准的请求;则 1 秒内按拒绝处理,解析返回结果或明确失败 | BR-01 |
