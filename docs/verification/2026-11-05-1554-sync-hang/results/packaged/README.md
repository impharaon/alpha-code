# 打包版样本(alpha-code#1554 AC2、AC3)

2026-11-05,已装 0.1.25(Electron 42.3.3 / Chromium 148.0.7778.218),owner 机。`--log-net-log` 在打包版上生效,4 份 netlog 都 `finalized=true`。只提交判定结果,netlog 全文未提交。

| 样本 | 场景 | 模型列表用时 | `probeTimeouts` | 卡住的样本 |
|---|---|---|---|---|
| cold-1 | 冷启动 | 232 ms | 0 | 0 |
| cold-2 | 冷启动 | 约 244 ms | 0 | 0 |
| cold-3 | 冷启动 | 约 256 ms | 0 | 0 |
| renew-f | 续期后新对话 ×3 | 模型读取 90 / 12.8 / 7.3 ms | 0 | 0 |

冷启动时引擎连接峰值到过 6,没有造成排队。

结论:H1(界面端同源连接排队)是修前 42 秒卡顿的原因,在 #1563 之前的树上 3/3 复现;0.1.25 上这 6 个样本都没有出现卡顿。

## 局限
- 只有这一台机器、一晚的样本。
- 输入框下的等待行在 0.1.25 的文案是「正在读取模型状态」,样本没有逐 100 毫秒捕捉到它;依据是模型读取时长和点击后约 250 毫秒的截图,更短的闪现排除不了。
- 续期样本选中的都是自带 Key 的 `deepseek-flash`,没有覆盖平台模型;单窗口;没有配不应答的第三方连接器(回归格 R10 覆盖)。
- 第一轮 dev 夹具看到的「冷启动引擎 10–35 秒不回首批请求」在这 3 轮里没有出现,原因没有查。
